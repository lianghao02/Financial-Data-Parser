# 專案特定細則：金融資料 CSV 轉 Excel 工具 (Financial Data Parser Rules)

> [!IMPORTANT]
> 本專案嚴格受「全域大腦 v2.1.0 (Tech Lead)」規範。所有開發計畫、UI 介面與註解文件必須 100% 使用台灣繁體中文。請保持專業、直接的 Tech Lead 溝通口吻，去除不必要的 AI 罐頭語氣。

## 1. 核心業務邏輯 (Financial Data Logic)
- **帳號強型別保護**：
  - 強制將所有帳號、身分證字號、銀行代碼識別為「字串 (String)」。
  - 必須精準運用 SheetJS 的 `t: 's'` 屬性寫入單元格，嚴禁出現科學記號或移除前導零，這是金融資料的鐵律。
- **智慧金額清理 (Regex Logic)**：
  - 必須嚴格過濾 `$`, `+`, `,` 及等號。
  - 特別針對 `.0+` 後綴（如 `.00`, `.000`）進行全數清空，無縫轉換為純整數。
- **ZIP 遞迴處理**：
  - 支援前端解壓縮（利用 JSZip CDN，貫徹離線運算精神）。
  - 若偵測到 ZIP 內還有 ZIP，必須確實進行遞迴提取，直到取得所有目標 CSV/Excel 檔案為止。

## 2. 匯出模式實作規範
- **個別儲存**：一對一產生獨立檔案。
- **分頁合併**：多對一，每個檔案獨立為一個 Sheet。分頁命名請確實遵循 `自訂前綴 + 序號` 的邏輯。
- **單頁堆疊 (Vertical Stack)**：
  - 多對一，所有資料必須乾淨地集中在同一個 Sheet。
  - **自動除重**：僅保留第一份檔案的標題列，後續檔案僅提取資料列，確保整併後的資料表毫無瑕疵。

## 3. UI 配置與持久化 (UI-Driven Pattern)
依據防禦性與美學設計，必須在網頁側邊實作高質感的設定面板，並包含以下連動功能：
- **參數設定**：
  - `EXCEL_FORMAT`: 下拉選單 (文字/數值/自動)。
  - `CLEAN_AMOUNT`: 開關 (移除符號與小數點)。
  - `MERGE_MODE`: 下拉選單 (個別/分頁/單頁堆疊)。
- **持久化要求**：
  - 所有 UI 調整後的數值必須存入 `localStorage`，頁面重新整理後需精準回填。
- **極致美學與主題切換**：
  - 介面設計必須具有現代感。提供 `THEME_COLOR` 選擇器，並透過 CSS 變數 `--primary-color` 全局套用，提升使用者的沉浸感。

## 4. 效能與防禦性設計
- **載入遮罩 (Loading Mask)**：處理 50MB 以上的龐大檔案或執行解壓縮時，必須顯示具備設計感的全螢幕 Loading 遮罩，安撫使用者等待情緒。
- **錯誤提示 (Error Handling)**：若 CSV 解析失敗，必須立刻彈出帶有 ⚠️ 標籤的繁體中文提示（需包含確切的錯誤行數），嚴禁發生讓使用者不知所措的靜默崩潰。
